## 改用 SSH 推送（用户要求直接试）

- 生成 ed25519 密钥：`C:\Users\小肥\.ssh\id_ed25519`（注释 `xingrenshun@workbuddy-20261010`）。
- **22 端口被 Clash 假 IP `198.18.0.241` 挡掉**（DNS 被 Clash fake-IP 劫持，SSH 走默认 22 超时）。
  **改用 443 端口走 `ssh.github.com`** 直连成功（本机直连 GitHub 443 通，比代理稳）。
- OpenSSH 的 `~` 取自 passwd 库而非 `$HOME`，本机 HOME 是非 ASCII（`小肥`）被 MSYS 编成乱码路径，
  导致 `~/.ssh/config` 读不到 → 默认回退 22 端口。解法：不依赖 config 文件，直接给 git 设
  `core.sshCommand="ssh -p 443 -o HostName=ssh.github.com -i /c/Users/小肥/.ssh/id_ed25519 -o UserKnownHostsFile=/c/Users/小肥/.ssh/known_hosts -o StrictHostKeyChecking=accept-new"`。
  另写了 `C:\Users\小肥\.ssh\config`（无 IdentityFile，让原生 OpenSSH 自动找默认 id_ed25519）供 SourceTree 用。
- remote 已切到 SSH：`git@github.com:xingrenshun/ZuiJiasheshou.git`。
- **卡点**：`~/.git-credentials` 里的 `gho_` OAuth token 权限只有 `gist, repo, workflow`，
  没有 `write:public_key`，**无法用 API 把公钥注册到 GitHub**（POST /user/keys 返回 404）。
  → 必须用户在 GitHub 网页端手动粘贴公钥（Settings → SSH and GPG keys）。公钥已就绪，待用户贴入后即可 `git push` 验证。
